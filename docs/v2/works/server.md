# Server:路径的 CRUD + blob 出口

> `cb serve` 干两件事:**一组路径上的增删改查**(网页是它的客户端),**把 blob 传到对象存储**。
>
> 主设计见 [`../DESIGN.md`](../DESIGN.md);blob 机制见 [`blob-store.md`](blob-store.md);守卫见 [`cli.md`](cli.md) §4。

---

## 0. 定位

- **可选。** 不跑它整套机制照常工作——分层、校验、投影、blob 转换全在 git hook 里。它挂了仓库不受影响。
- **没有特权。** 它写的每个提交都要过和别人完全相同的那道闸(`reference-transaction`)。没有旁路。
- **不是 git server。** 不提供 clone / push,那是主设计 §14 的事。

它补两个缺口:仓库不自足(clone 不带 blob 字节),以及**媒体没有界面**——命令行看不了图、听不了音、翻不了 PDF,而事实层里恰恰全是这些。

## 1. CRUD

```
读   GET  /files/<path>?view=<层|all>     文件内容
     GET  /files/<dir>/?view=<层|all>     列目录:名字、大小、归属层、最后修改
写   POST /commit    {layer, message, ops: [put(path, bytes) | delete(path)]}
```

**写是一个批量端点,不是逐路径 PUT。**提交是变更的单位:拖进 5 个文件是一次动作,改名是"新增 + 删除"同时发生,都该是一个提交。一批 ops → 一个提交,顺带把多文件上传、批量删除、改名全覆盖了。

**`view` 和 `layer` 是两回事。**`view` 是读哪一层的视图(`facts` = 只看事实层,`all` = 完整堆叠);`layer` 是写入时声明属于哪一层,变成 `[层名]` 前缀。网页上把两者绑起来是个好默认,API 层面得分开。

三条规矩:

1. **呈现文件,不呈现 git 对象。** 读一个 `120000` 条目返回的是字节;写二进制由 server 转 blob。调用方不知道 blob 机制存在。
2. **规则一条都不实现。** 删下层文件、写别层占用的路径、传 submodule——server 照做,然后守卫拒绝整个事务,server 把那段话当 `409` 的 body 原样返回。页面上显示的字就是命令行里会看到的字。
3. **改 `layers` 不需要特殊支持。** 加一层就是往 `layers` 这个路径 put 一次,`layer` 填最底层。锚定文件是普通路径,CRUD 已经覆盖。

## 2. 三个由此落定的点

**① hook 和 server 是同一个库的两个入口。**

server 走 plumbing,hook 一个都不触发,所以它得自己做 hook 做的事。这些逻辑因此不能只活在 hook 脚本里:

```
collectbase(库)
  blobify / validate / project / commit
        ↑                ↑
      hook 调         server 调
```

库是产品,hook 只是入口之一。这也是它得是个 pip 包而不是几个 shell 脚本的原因。

**② 我漏了一个洞:server 的提交不会被投影。**

上一版说"server 走 plumbing,守卫照样校验它"——对,但没往下想:`post-commit` 也不跑,而**投影和重算正是在 `post-commit` 里做的**。于是 server 每写一次,`layer/*` 就落后一次,I2 被持续破坏,而守卫看不出来(它只查写入面上的提交本身)。

修法就是 ①:`project()` 是库函数,`commit()` 内部调它。顺带这解释了 [`cli.md`](cli.md) §4 那条"写入面领先于投影时拒收新提交"为什么必要——它是这类漏洞的兜底。

**③ 不要锁,用乐观重试。**

并发写时第二个人的 `old` 已经过期,守卫的 FF 检查天然拒绝该事务(明确失败,不是丢失更新)。所以被拒就用新 tip 重算一遍再试。路径不冲突必然成功;真冲突就是最后一个赢,和文件管理器的直觉一致。比锁简单,也不会有"锁没释放导致整个仓库写不进去"。上一版的提交锁作废。

> 还剩一件小事:如果有工作区正 checkout 在写入面上,`update-ref` 之后要把这次涉及的那几个精确路径写进工作区并更新索引——否则它的 HEAD 动了、磁盘没动,`git status` 会把新文件显示成已删除。

## 3. 网页

就是上面这套 CRUD 的一个客户端,没有额外的服务端逻辑。

```
┌─ 视图: [ 全部 ▾ ] facts · notes · beliefs ──────────────────┐
│  project/                                                    │
│    api.md                        facts    2.1 KB   08-14     │
│    api-notes.md                  notes    5.7 KB   08-13     │
│    log/screen.png                facts     5 MB    08-14  ▣  │
│  [ 拖拽文件到这里 → 写入当前视图对应的层 ]                     │
└──────────────────────────────────────────────────────────────┘
```

分层给它的东西只有两样,都是白送的:**视图切换**,以及**归属层那一列**——归属表本来就现成,而这一列把"这是观测还是推论"变成肉眼可见的属性,正是 v2 想表达的东西。

图片、PDF、音频直接预览,于是 blob 的日期分片布局终于兑现成一个能翻的媒体库。

没有分支、没有 diff、没有历史图。要那些的人手边就有 git。

**默认只听 `127.0.0.1`。**这个接口能往事实层写,是整套设计里信任度最高的位置。不配 token 就拒绝绑定非回环地址,启动时直接报错。

## 4. blob 出口

后端四个方法:`exists` / `put` / `get` / `list`。一份 S3 兼容实现覆盖 S3 / OSS / R2 / MinIO,外加一个 `file://` 后端(就是个目录)。

**远端走纯 CAS,本地保留日期分片:**

```
本地   blob/2026/07/23/f1a4f247…ac.png     日期分片,为了能当媒体库浏览
远端   f1/a4/f1a4f247…ac.png               纯 CAS,为了去重
```

同一份内容在不同日子被添加会产生两个本地路径([`blob-store.md`](blob-store.md) §3 的已知代价),远端照抄就要付两份存储费。恢复不需要额外映射:软链目标里同时含日期路径和 sha256。

**什么时候传:**周期扫描 `blob/` 是保证;`post-commit` poke 一下 `127.0.0.1` 是优化,**poke 失败必须完全忽略**——server 没起不能让提交失败。上传幂等(key 是内容哈希,`exists` 为真就跳过)。

三条规矩:

1. **对象写一次不再改。** 建议 bucket 开版本控制或 WORM——**能写这个 bucket 的人就能替换事实层的截图**,这是 DESIGN §13 ② 那个洞在远端的镜像。
2. **永不删远端对象。** 远端可能被别的 clone 引用,清理要另外的、跨仓库取并集的流程。
3. **上传失败不阻塞任何东西。**

**反向:**clone 之后或 `git clean -xdf` 之后本地 `blob/` 是空的,server 启动时对照活集拉回缺失的部分。写盘前验 sha256,已存在且正确的跳过,已存在但哈希不对的**报错而不是覆盖**——那是 `cb check` I5 要人看的现场。

## 5. 配置

不进仓库(机器级,含凭证):

```yaml
# ~/.config/collectbase/server.yaml
repo:  /home/me/notes
bind:  127.0.0.1:8787
token: ""                     # 绑定非回环地址时必填

blob_store:
  kind:     s3                # s3 | file
  endpoint: https://oss-cn-hangzhou.aliyuncs.com
  bucket:   my-collectbase
  prefix:   blob/
  access_key_id:     "…"
  access_key_secret: "…"
  scan_interval: 5m
```

仓库里的 `.collectbase/config.yaml` 只放与仓库有关的可调项(blob 阈值、`force_in` / `force_out`)。两者不混。

## 6. 里程碑

排在主设计 M4 之后。**前提**:M1–M4 得先把 `blobify` / `validate` / `project` / `commit` 抽成库函数(§2 ①),否则 server 只能复制一份逻辑。

- **S1** — blob 出口:四方法 + S3 实现 + 周期扫描 + 启动时补齐缺失。命令行先行。
- **S2** — 读:`GET /files/…`,视图切换、按层标注、预览、下载。
- **S3** — 写:`POST /commit`,批量 ops、乐观重试、工作区路径同步、拒绝信息透传。
- **S4** — poke;`file://` 后端。

## 7. 待定

- **层权限。** 单机单人不需要;配了 token 对外开放之后,要不要区分"谁能写事实层"?
- **超大文件。** 浏览器直传对象存储(预签名 URL)再提交软链,还是走 server 落盘?前者省一次中转,但要客户端先算 sha256。
- **多仓库共用一个 bucket。** CAS 布局天然支持,但远端 GC 的活集要跨仓库取并集,谁维护那份清单。
- **断点续传。** 录屏动辄几百 MB。
